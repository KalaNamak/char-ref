# Character Reference Builder

A small client-side tool for drafting a character reference for a UK
Crown Court defendant, formatted as a Section 9 (Criminal Justice Act
1967) statement of witness: fill in a form, watch a live preview, sign
it on screen, and download it as a PDF. No backend — everything runs in
the browser.

**About the statement format:** the document opens with a case caption
and a declaration of truth (the standard Section 9 wording), signed and
dated there, rather than being addressed as a letter — there's no "Dear
Sir/Your Honour" salutation or "Yours faithfully" sign-off. Every page
carries a footer with the signature and "Page x of y", calculated
exactly via a two-pass render (see `buildPdfBlob()` in `app.js`). A few
simplifications worth knowing about:
- The age field always prints "Age: Over 18" — there's no age/date of
  birth field in the form, since this is built for adult referees. If
  you need to support under-18 witnesses, you'll want to add a proper
  age/DOB field and branch the wording in `app.js`.
- The statutory reference under the title is kept to just "(Criminal
  Justice Act 1967, s.9)" rather than also citing a specific Criminal
  Procedure Rules paragraph — those rule numbers get renumbered from
  time to time, so it felt safer to leave that out than risk printing a
  stale citation. Add it back in `renderStatementDoc()` /
  `renderPreview()` if your solicitor wants it.
- This is a reasonable starting structure, not a guarantee of
  admissibility — have the receiving solicitor check the final document
  before it's relied on.

## Files

```
index.html   structure/markup, all the form fields
styles.css   colours, fonts, layout (see comments at the top)
app.js       form state, live preview, signature capture, PDF export
```

## Running it locally

Just open `index.html` in a browser — there's no build step. If your
browser blocks local file access for the fonts/PDF library, serve it
with any static server, e.g.:

```bash
python3 -m http.server 8000
# then visit http://localhost:8000
```

## Deploying to GitHub Pages

1. Create a new GitHub repository and push these three files (plus this
   README) to it, e.g.:
   ```bash
   git init
   git add .
   git commit -m "Character reference builder"
   git branch -M main
   git remote add origin https://github.com/<you>/<repo>.git
   git push -u origin main
   ```
2. On GitHub, go to **Settings → Pages**.
3. Under **Build and deployment**, set **Source** to "Deploy from a
   branch", branch `main`, folder `/ (root)`.
4. Save. GitHub will give you a URL like
   `https://<you>.github.io/<repo>/` within a minute or two.

No configuration files are needed — `index.html` at the repo root is all
GitHub Pages requires.

## Customising

**Add a field** (e.g. "how long you've known the defendant"):
1. In `index.html`, copy an existing `.field` block and give the input a
   new `id`.
2. In `app.js`, add the key to the `state` object at the top and to the
   `simpleFields` array so it's wired up automatically.
3. Add a line for it in `renderPreview()` so it shows in the live
   preview, and in `renderStatementDoc()` so it appears in the PDF.
4. If it should be required before the PDF can be downloaded, add its
   key to `requiredFields` and a short label to `fieldLabels`.

**Change the document's wording, order, or template structure:**
Edit `renderPreview()` (screen) and `renderStatementDoc()` (PDF content —
called by `buildPdfBlob()`, which handles the two-pass page-counting and
footers separately) in `app.js` — they're built to mirror each other
section by section, so change both together or the preview will drift
from the download. The opening paragraph is a
special case: it's generated by `generateOpeningDraft()` into an
editable textarea (`#f-opening`) rather than being fixed text, so the
person filling in the form can rewrite it in their own words. It
re-generates automatically as the fields above it change, until the
person edits it directly (tracked via `state.openingTouched`), or clicks
"Regenerate from details above" to reset it.

**Change the footer or page margins (PDF):**
`PDF_MARGIN_LEFT`/`RIGHT`/`TOP`/`BOTTOM` and `PDF_PAGE_WIDTH`/`HEIGHT`
near the top of the PDF section in `app.js` control the page geometry;
`drawPdfFooter()` controls what's drawn in the footer itself. The bottom
margin is deliberately large (34mm) to leave room for the footer without
body text overlapping it — if you resize the footer, keep that margin
big enough to clear it.

**Change fonts:**
- UI font (labels, buttons): the `--font` used in `body` in
  `styles.css`, currently Inter.
- Letter/document font: `.paper-wrap` in `styles.css`, currently Source
  Serif 4. To change the actual PDF font too, see the comment above
  `doc.setFont(...)` in `renderStatementDoc()` — jsPDF only has
  Helvetica/Times/Courier built in, so an exact match in the PDF needs a
  font embedded as base64 (jsPDF's "Add Custom Fonts" docs cover this).
- Signature font: search for `Dancing Script` in both files.
- Whichever fonts you use, update the Google Fonts `<link>` tag in
  `index.html` to match.

**Change colours/layout:**
The palette is defined as CSS variables at the top of `styles.css`
(`--bg`, `--ink`, `--accent`, etc.), including a dark-mode variant.
Layout (the two-column grid, spacing, card styling) is further down the
same file.

## Notes

- Nothing is saved or sent anywhere — all data lives in memory in the
  visitor's browser tab until they download the PDF.
- This produces a solid first draft of a standard-format letter; it
  isn't legal advice, and it's worth having a solicitor glance over the
  final letter before it's submitted to the court.
